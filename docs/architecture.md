# Architecture

```
src/
  main.py                 entry point for the window
  project.py              projects/ files
  settings/main.py        WINDOW, EMULATION, PATHS
  emulator/               no Qt anywhere in here
    versions.py           version ordering, ranges, formats, feature queries
    version_data.py       GENERATED by tools/generate_version_data.py
    vanilla.py            client.jar reader and jar library
    common.py             tokenize, SNBT, NBT paths, text components, ranges
    costs.py              cost model
    resources.py          Resource, JsonResource, Tag, Function, …
    namespace.py          Namespace, DirectoryNode, registry folder names
    datapack.py           PackMCMETA, PackPNG, OverlayEntry, Layer, PackView, Datapack
    commands/
      parser.py           Selector, Subcommand, Command (parse, features, cost, macros)
      result.py           CommandResult
      handlers.py         cmd_* implementations and the HANDLERS table
      registry.py         CommandSet: what exists in a version, who runs it
    runtime/
      output.py           LogSource, LogLevel, LogRecord, OutputBus
      messages.py         vanilla strings, MessageCatalogue
      world.py            Entity, Scoreboard, World, selector resolution
      context.py          ExecutionContext (the command source)
      emulator.py         Emulator: load/tick loop, dispatch, functions, schedules
    analysis/
      profiler.py         Profiler and its HTML report
      graph.py            CallGraph
    engine.py             TestEngine, VersionRun
    __main__.py           CLI
  window/                 Qt only
    window.ui, engine.ui  ALL layout (plus download.ui)
    main.py               MainWindow: wiring
    engine_window.py      EngineWindow: wiring
    download.ui           client-jar download popup
    download_dialog.py    DownloadDialog + DownloadWorker (QThread)
    panels/
      uiloader.py         load a .ui into an existing QMainWindow
      explorer.py         explorer model
      inspector.py        inspector rows
      logs.py             log table model and filters
      results.py          engine results model
      graph.py            pyqtgraph DAG canvas with node hit-testing
      highlight.py        .mcfunction and JSON highlighters
tools/generate_version_data.py
tests/       pytest suite; conftest.py builds synthetic packs and client jars
.github/     CI workflow, Dependabot, issue and pull request templates
docs/

projects/    saved projects (git-ignored)
generated/   reports and .dot files (git-ignored)
.cache/      downloaded client jars (git-ignored)
```

## Data flow of a run

```
Datapack.load(path) ──► base Layer + overlay Layers
        │
        ▼ view_for(version)
     PackView ─────────────────────────────┐
        │                                  │
        ▼                                  ▼
Emulator(pack, version, vanilla, output)  CallGraph.from_pack
        │ run_function → run_command
        │     CommandSet.spec(name)   ── version_data
        │     handler(command, context)
        │         World / ExecutionContext
        │         context.chat / feedback / game_error ── MessageCatalogue ── client.jar
        ▼
   OutputBus ──► logs dock, engine window, CLI
   Profiler  ──► profiler tab, HTML report
```

## Rules of the codebase

* **Version logic lives in `versions.py`.** Anything else asks it; nobody
  compares version strings or pack formats inline.
* **Base-game facts come from data**, not code: the generated version table
  or a client jar. If you are about to type a list of vanilla ids, read them
  from `VanillaAssets` instead.
* **`src/datapack_emulator/emulator` never imports Qt**; the window is one consumer among the
  CLI and tests.
* **All layout is in `.ui` files.** Python looks widgets up by object name.
  The only widget created in code is the pyqtgraph canvas, which Designer
  cannot describe; it goes into the `graphContainer` placeholder.
* **Game output and our diagnostics stay separate.** A handler reports what
  Minecraft would say with `context.game_error(key, …)` using a real
  translation key; what *we* notice goes through `context.note(…)`.
* **`runtime/__init__.py` re-exports nothing** — `handlers` imports
  `runtime.context` while `commands` is initialising; re-exporting the
  emulator there would create an import cycle. Import from `datapack_emulator.emulator`.
